8테스트와 회귀 스위트

P1부터 상시로 돌립니다. 전부 기존 연구의 방법을 그대로 씁니다.

지표 1
CED 회귀

그래프를 켠 초고와 끈 초고를 같은 프롬프트로 뽑아 1만 단어당 오류를 비교. ConStory-Checker의 4단계 파이프라인(범주별 추출 → 쌍 비교 → 증거 체인 → 문자 오프셋 앵커 JSON)을 그대로 구현.

지표 2
통제 모순 주입

FlawedFictionsMaker 방식 — 자기 소설에 의도적으로 모순을 심고 검출률 측정. evals/injected/에 케이스를 쌓습니다. 오염 없는 자체 회귀 스위트를 만드는 가장 싼 방법.

지표 3
토큰 예산

챕터 한 편 집필 시 컨텍스트에 들어간 인덱스 토큰. 8,000 초과하면 실패로 처리.

단위 테스트에서 반드시 다룰 것

  • 시간 구간 경계 — story_to가 null인 경우, 구간이 정확히 맞닿는 경우, 역전된 경우
  • 가시성 술어 — 네 가지 상태 각각의 최소 재현 케이스
  • 복선 상태 전이 — 불법 전이(트리거 없이 actualized)가 거부되는가
  • 충돌 판정 — 같은 필드/다른 필드, 리비전 일치/불일치 4조합
  • early cutoff — 정규화 투영이 같으면 전파가 멈추는가 (문자열은 달라도)
  • 순환 — causes 순환을 만드는 쓰기가 거부되는가
단일 스칼라로 튜닝하지 마세요

WSE-bench는 일관성과 풍부함의 파레토 경계가 non-concave라서 어떤 양의 선형 가중치로도 여러 비지배 구성을 고를 수 없다고 보고했습니다. 그리고 StoryRMB는 기존 보상 모델 최고가 66.3%에 불과하다고 보고했습니다. CED는 회귀 감시용이지 최적화 대상이 아닙니다. 일관성 점수 하나를 목적함수로 삼으면 재미없는 소설로 수렴합니다.

10하지 말아야 할 것

  • 파일 읽기를 감싼 얇은 MCP 툴을 만들지 마세요. 에이전트는 이미 파일 툴을 갖고 있습니다. MCP에는 에이전트가 스스로 못 하는 것만 — 상태를 들고 있는 것, 계산이 필요한 것, 챕터를 가로지르는 검색.
  • 노드 전문을 툴 결과로 반환하지 마세요. 주소를 돌려주고 에이전트가 따로 요청하게 하세요.
  • MCP prompts를 진입점으로 쓰지 마세요. Codex 클라이언트에 미구현입니다.
  • freshness 판단을 LLM에게 시키지 마세요. 버전 번호가 명시적으로 라벨링된 과제에서조차 실패합니다 — 추출(LLM)과 선택(결정론)을 분리하면 54% → 82%.
  • 믿음·상태를 in-place로 덮어쓰지 마세요. “그때 그녀는 아직 몰랐다”를 구조적으로 못 쓰게 됩니다.
  • 산문 속 언급을 자동으로 고치지 마세요. soft 간선은 보고만 합니다.
  • 캐스케이드가 canon을 자동 커밋하게 두지 마세요. 항상 제안으로.
