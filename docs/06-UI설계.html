UI 설계

화면 네 개의 정보구조와 상태, 컴포넌트 인벤토리, 디자인 토큰, 렌더러 선택 근거. 실제로 동작하는 목업은 07번 문서에 있습니다 — 먼저 열어보고 오세요.

대상 디자이너 · 개발자 단계 P4 목업 07-UI목업.html

1설계 원칙

원칙 1
전체를 그리지 않는다

장편 그래프는 수천 노드가 되지만 절대 한 화면에 다 그리면 안 됩니다. 3,000개를 한 번에 그리는 건 성능 실패이기 이전에 UX 실패입니다. 타입 필터, 초점+맥락, 요청 시 확장으로 항상 수백 개 이하만 보이게 합니다.

원칙 2
진단은 앰비언트로

모달 승인 다이얼로그를 쌓지 마세요. 맞춤법 밑줄처럼 항상 보이되 방해하지 않는 인라인 표시 + 묶음 검수 큐가 맞습니다. 제안이 쌓이면 사람은 전부 무시하게 됩니다.

원칙 3
출처를 항상 보여준다

모든 값 옆에 누가 언제 왜가 붙습니다 — 사람 / 에이전트 / 캐스케이드. 특히 사람의 편집과 캐스케이드 파생 편집을 시각적으로 구분하는 것이 핵심이고, 이건 공짜로 안 나옵니다.

원칙 4
원문으로 가는 길을 막지 않는다

모든 노드에서 근거 원문 조각으로 한 번에 갈 수 있어야 합니다. 요약이 최종 진실이 아니라 색인이라는 것을 UI가 계속 상기시켜야 합니다.

3화면 명세

3.1그래프 뷰

요소동작상태
캔버스배경 드래그로 이동, 휠로 확대·축소, “맞춤” 버튼으로 전체 보기idle · dragging
노드 카드클릭 → 인스펙터 채움. 폭 186px 고정, 타입 배지 + 제목 + 부제 + 태그 칩default · hover · selected · dimmed(필터 제외)

타입 필터토글 시 해당 타입 노드가 흐려짐(제거 아님) — 맥락 유지on · off
기준 시점슬라이더 이동 시 reveal_at > as_of인 노드 숨김1 ~ 마지막 장
범례좌하단 고정. 세 간선 종류 설명—
노드 카드에 무엇을 넣나

타입 배지 · 제목 · 부제(한 줄) · 태그 칩까지만. 본문은 절대 넣지 않습니다 — 카드가 커지면 화면에 들어가는 노드 수가 줄고, 그러면 그래프의 의미가 사라집니다. 상세는 전부 인스펙터에서.

3.2복선 보드

상태별 4열 칸반 — hypothetical / eligible / actualized / prevented. 카드마다 F · T · P 세 줄과 측정값(S-Eff, Δ-Coh, 부채)이 붙습니다.

열색의미주의 신호
hypothetical위험심겼지만 트리거 미정원고가 끝나가는데 남아 있으면 방치된 복선
eligible대기트리거 발화, 회수 가능오래 대기하면 독자가 잊음
actualized완료회수됨S-Eff가 높으면 너무 티났던 것
prevented중립의도적 폐기 (레드헤링)—

이 화면이 제품의 차별점을 눈으로 보여주는 곳입니다. 다른 도구에는 이 화면이 없습니다.

3.3이중 시간축

가로축은 독자에게 드러난 순서(discourse), 세로 위치는 작중 실제 시간(story). 선이 단조 증가하면 시간순 서술이고, 아래로 꺾인 지점이 회상입니다.

이 꺾임은 작가가 “여기는 회상”이라고 태그해서 나오는 게 아니라 story_from < reveal_at인 노드를 그대로 그린 것입니다 — 두 필드의 불일치가 곧 그림입니다.

3.4검수 큐

제안 카드 구성내용
헤더제목 · 위험 등급 배지(자동승인 가능 / 검토 필요 / 충돌) · 모델·세션 ID
근거에이전트가 쓴 rationale 한 문단
op 목록+ 추가 / ~ 변경 / − 무효화. 변경은 이전값 새값 인라인 diff
충돌 설명충돌 시에만. 왜 보류됐는지를 리비전과 함께 설명
read set근거로 읽은 노드와 리비전. 낡은 것은 취소선
동작승인 / 영향 미리보기 / 보류
diff 뷰는 제품 기능입니다

Ink & Switch가 Patchwork에서 얻은 교훈 — “브랜치와 타임라인은 붙이기 쉽지만 diff는 도메인별 커스터마이즈를 요구한다.” 그들이 스프레드시트에서 막힌 지점이 사용자 편집과 수식 재계산 결과를 구분하는 것이었고, 여기서는 사람의 편집과 캐스케이드 파생 편집을 구분하는 것입니다. 파생 편집은 쓰기 시점에 origin: "cascade"로 태깅해야 합니다. 나중에는 구분할 수 없습니다.

레이아웃은 elkjs(EPL-2.0)를 붙입니다 — 중첩 compound를 지원하는 계층 레이아웃으로는 이게 최선이고 React Flow 서브플로우와 짝이 맞습니다.

성능이 아니라 UX 요구사항

React Flow의 300–800 한계가 문제로 보이지만, 애초에 그 이상을 그리면 안 됩니다. 렌더러 선택이 병목이 되는 상황 자체가 UI 설계가 틀렸다는 신호입니다.

7내보내기

  • JSON Canvas(Obsidian) — 뷰 내보내기용으로만. 임의 메타데이터를 노드에 못 붙이고 타입 간선도 없어서 진실의 원천으로는 절대 쓸 수 없지만, 부분 뷰를 Obsidian에서 열어보게 하는 용도로는 충분합니다.
  • Arcweave JSON — 씬 플로우 계층의 상호운용 대상. 상용 서사 도구 중 유일하게 공개·문서화된 포맷입니다.
  • SVG / PNG — 복선 보드와 이중 시간축은 그대로 이미지로 뽑을 수 있어야 합니다. 기획 회의에서 쓰이는 화면입니다.

8접근성과 반응형

  • 라이트/다크 자동 대응 — 토큰 수준에서 정의. 세 상태(명시적 light / 명시적 dark / 시스템)를 모두 처리합니다.
  • 키보드 — ⌘K 옴니 검색, Tab 노드 순회, Esc 선택 해제. 모든 포커스에 가시적 링.
  • prefers-reduced-motion — 캔버스 전환 애니메이션 제거.
  • 좁은 화면 — 1100px 미만에서 레일과 인스펙터를 접고 캔버스만. 복선 보드와 검수 큐는 단일 열로.
  • 색에만 의존하지 않기 — 간선 종류는 색 + 선 스타일 둘 다로 구분합니다. 진단 심각도는 색 + 아이콘.
